# API Parity Audit — FoundationModels SDK 27 vs LinuxFoundation

Date: 2026-06-12 · Generated by `scripts/api-audit.py` against
`reference/FoundationModels-macOS27.swiftinterface` (verified identical
top-level type set to the iOS 27 interface in the same Xcode beta).

## Scorecard (updated after batches 1-7)

| Metric | Apple ships | We have | Missing |
|---|---|---|---|
| Public types + macros | 151 | 151 | **0** |
| Public members on types we have (name-level) | 482 | 482 | **0** |

Synthesized members (Hashable `hash`/`hashValue`, CaseIterable `allCases`),
protocol-extension defaults (`prewarm`), and extensions on nested protocols
(the channel `Event` constructors, exercised by ClaudeForFoundationModels)
are excluded as parser false positives — all verified present.

Known signature-level refinements remaining (name matches, shape differs):
`ImageAttachment.pixelBuffer` is a var here vs Apple's
`pixelBuffer(resolution:pixelFormat:) throws -> CVReadOnlyPixelBuffer`;
`@Generable` macro synthesizes `PartiallyGenerated = Self` rather than an
all-optional-fields struct (typed streaming snapshots); `GenerationGuide
.pattern(Regex)` is advisory. The definitive closure is the emitted-interface
diff gate in CI.

## Method note

Name-level matching can hide signature drift within same-named members;
once the batches land, the definitive gate is compiling Apple-written client
code (the parity suite, Origami fixtures, ClaudeForFoundationModels) plus a
signature-level diff of our emitted `.swiftinterface` against the reference —
tracked as the CI interface-diff gate.
